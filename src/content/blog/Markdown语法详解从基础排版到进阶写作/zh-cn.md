Markdown 的魅力在于：用接近纯文本的写法，就能组织出清晰、可读、适合发布的结构化文档。它既适合记录学习笔记，也适合编写项目说明、博客文章、实验报告和技术文档。

本文从最常用的基础语法讲起，再逐步扩展到表格、任务列表、代码、数学公式和 HTML 等进阶写法。示例中的 Markdown 代码块可以直接复制到支持 Markdown 的编辑器中尝试；不同网站的渲染器可能存在细节差异，因此发布前最好预览一次最终效果。

## 一、Markdown 文档的基本结构

一篇可读的 Markdown 文章通常由标题、段落、列表、代码示例和必要的说明组成。建议先确定文章的层级结构，再填充具体内容，这样能够让目录、搜索和后续维护都更加清晰。

### 1. 标题与层级

使用一个到六个井号表示标题，井号与标题文字之间需要保留空格：

~~~markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
~~~

`#` 通常用于文章主标题，`##` 用于主要章节，`###` 用于章节下的细分主题。一个页面最好只保留一个一级标题，层级也应尽量连续，避免从 `##` 直接跳到 `####`。

也可以使用 Setext 风格的一级和二级标题：

~~~markdown
一级标题
========

二级标题
--------
~~~

这种写法较少用于复杂文章，但在简单说明文档中仍然有效。

### 2. 段落与换行

连续的一行或多行文字会组成同一个段落。段落之间空一行：

~~~markdown
这是第一段。它可以包含多句说明，
编辑器中的自然换行不一定会变成最终页面中的换行。

这是第二段。空行会明确告诉 Markdown：
这里开始了新的内容单元。
~~~

如果需要在同一段中强制换行，可以在行尾添加两个空格，再回车；也可以使用反斜杠：

~~~markdown
第一行  
第二行

第一行\\
第二行
~~~

在技术文章中，段落之间使用空行通常更容易维护；只有诗歌、地址或明确需要逐行显示的内容才建议频繁使用强制换行。

## 二、文字强调与行内代码

### 1. 粗体、斜体和删除线

Markdown 使用星号或下划线表示强调：

~~~markdown
*斜体文字*
_斜体文字_

**粗体文字**
__粗体文字__

***粗斜体文字***

~~删除线文字~~
~~~

渲染效果如下：

- *斜体文字* 常用于轻量强调；
- **粗体文字** 适合突出关键概念；
- ~~删除线文字~~ 可以表示废弃内容或修订痕迹。

强调应该服务于阅读，不要让整段文字都变成粗体，否则重点反而会消失。

### 2. 行内代码

命令、函数名、变量名、文件名和短代码片段适合使用反引号：

~~~markdown
使用 `git status` 查看仓库状态。
C 语言函数 `fopen()` 接收一个文件路径和打开模式。
~~~

行内代码不宜包裹过长的段落。如果内容内部本身包含反引号，可以使用两个或更多反引号包裹：

~~~markdown
``这里包含一个 ` 反引号``
~~~

## 三、列表与清单

### 1. 无序列表

使用 `-`、`*` 或 `+` 加空格创建无序列表：

~~~markdown
- 安装编译器
- 编写源代码
- 编译并运行程序
~~~

列表项目可以嵌套，子项目通常缩进两个或四个空格：

~~~markdown
- 开发环境
  - 编译器
  - 调试器
- 构建工具
  - make
  - CMake
~~~

### 2. 有序列表

使用数字加句点创建有序列表：

~~~markdown
1. 准备输入文件
2. 执行处理命令
3. 检查输出结果
~~~

即使源码中每一项都写成 `1.`，多数渲染器也会自动显示连续编号。为了让源码本身更容易阅读，复杂步骤仍建议手动写出正确编号。

### 3. 任务列表

支持 GFM 的渲染器可以识别任务列表：

~~~markdown
- [x] 完成环境配置
- [x] 编写测试用例
- [ ] 补充异常分支测试
~~~

它适合项目待办、文章发布检查和实验进度记录。`[x]` 表示完成，`[ ]` 表示未完成。

## 四、链接与图片

### 1. 普通链接

基本链接语法为：

~~~markdown
[链接文字](https://example.com)
~~~

也可以添加鼠标悬停时显示的标题：

~~~markdown
[项目主页](https://example.com "打开项目主页")
~~~

如果希望直接显示 URL，可以使用尖括号：

~~~markdown
<https://example.com>
<example@example.com>
~~~

### 2. 引用式链接

当一篇文章中多次使用同一个链接时，可以把地址集中放在文末：

~~~markdown
请阅读 [项目文档][docs]，也可以查看 [源码仓库][repo]。

[docs]: https://example.com/docs "项目文档"
[repo]: https://github.com/example/project "源码仓库"
~~~

这种写法能让正文更干净，修改链接地址时也更集中。

### 3. 图片

图片语法与链接类似，只需在前面增加感叹号：

~~~markdown
![一张示意图](./images/demo.png)
~~~

推荐为图片填写有意义的替代文字。它既能在图片加载失败时提供信息，也有助于无障碍阅读和搜索引擎理解图片内容。

图片也可以指定标题：

~~~markdown
![终端输出示意图](./images/terminal.png "命令执行结果")
~~~

不同站点对图片尺寸、懒加载和相对路径的处理不同。发布前应确认图片文件确实位于文章可访问的目录中。

## 五、引用、分隔线与转义

### 1. 引用

在行首使用 `>` 创建引用：

~~~markdown
> 好的文档不仅记录结论，也记录得出结论的过程。
~~~

引用可以嵌套：

~~~markdown
> 第一层引用
>
> > 第二层引用
~~~

引用适合放置定义、提示、注意事项或来自其他资料的短摘录。较长的解释应直接写成普通段落，以免页面层级过深。

### 2. 分隔线

单独一行使用三个或更多 `-`、`*` 或 `_` 可以生成水平分隔线：

~~~markdown
---
***
___
~~~

为了避免和 YAML frontmatter 或列表产生歧义，分隔线前后最好各保留一个空行。

### 3. 特殊字符转义

当文字中需要显示 Markdown 保留字符时，可以在前面加反斜杠：

~~~markdown
\*这不会变成斜体\*
\# 这不会变成标题
\[这不会变成链接\]
~~~

常见可转义字符包括反斜杠、反引号、星号、下划线、花括号、方括号、圆括号、井号、加号、减号、句点和感叹号。是否需要转义，取决于字符所在位置以及你希望它被解析为语法还是普通文字。

## 六、代码块与语法高亮

### 1. 围栏代码块

使用三个反引号包裹多行代码，并在开头标注语言：

~~~markdown
\`\`\`c
#include <stdio.h>

int main(void) {
    puts("Hello, Markdown!");
    return 0;
}
\`\`\`
~~~

语言标识通常写成 `c`、`cpp`、`python`、`javascript`、`bash`、`json` 或 `markdown`。它能帮助渲染器选择语法高亮规则，也让读者更快判断示例用途。

### 2. 缩进代码块

旧式 Markdown 也支持每行缩进四个空格：

~~~markdown
    printf("indented code block\\n");
~~~

围栏代码块更适合现代技术文档，因为它支持语言标识、不需要手动缩进整段内容，也更便于复制和编辑。

### 3. 代码中的反引号

如果要展示包含三个反引号的 Markdown 代码，可以使用四个反引号作为外层围栏：

~~~~markdown
\`\`\`markdown
# 这是被展示的 Markdown
\`\`\`
~~~~

代码块中的内容通常不会解析为 Markdown，因此标题、星号和链接都会以代码形式显示。

## 七、表格

Markdown 表格至少需要表头、分隔行和数据行：

~~~markdown
| 工具 | 用途 | 常用命令 |
| --- | --- | --- |
| Git | 版本控制 | `git status` |
| GDB | 程序调试 | `gdb ./app` |
| make | 自动构建 | `make` |
~~~

渲染为：

| 工具 | 用途 | 常用命令 |
| --- | --- | --- |
| Git | 版本控制 | `git status` |
| GDB | 程序调试 | `gdb ./app` |
| make | 自动构建 | `make` |

可以在分隔线中使用冒号设置对齐方式：

~~~markdown
| 左对齐 | 居中 | 右对齐 |
| :--- | :---: | ---: |
| A | B | C |
~~~

表格适合比较结构化信息，但不适合放置很长的段落、复杂代码或多层嵌套列表。移动端页面尤其需要注意列数和单元格长度。

## 八、HTML 与特殊排版

多数 Markdown 实现允许在文档中混用少量 HTML：

~~~markdown
<p>这是一段使用 HTML 标签包裹的文字。</p>

<details>
<summary>点击展开更多说明</summary>

这里是折叠内容。

</details>
~~~

HTML 的兼容程度取决于站点安全策略和 Markdown 渲染器。公开文章中应避免插入不必要的脚本、事件属性或来源不明的 HTML；如果普通 Markdown 已经能够满足需求，优先使用 Markdown。

行内 HTML 也可以用于少量排版：

~~~markdown
这是 <kbd>Ctrl</kbd> + <kbd>C</kbd> 的快捷键说明。
~~~

## 九、数学公式

支持数学扩展的 Markdown 渲染器通常使用单个反斜杠括号表示行内公式，使用双美元符号表示独立公式：

~~~markdown
行内公式：\\(E = mc^2\\)。

$$
\\sum_{i=1}^{n} i = \\frac{n(n+1)}{2}
$$
~~~

行内公式适合嵌入概念说明，独立公式适合较长或需要单独强调的推导。数学语法通常基于 LaTeX，不同站点支持的宏命令可能略有差异；发布前应在目标网站中预览。

## 十、脚注、自动链接与扩展语法

部分 GFM 或扩展 Markdown 渲染器支持脚注：

~~~markdown
Markdown 追求可读性与易维护性。[^1]

[^1]: 这是脚注内容，可以放在文章末尾。
~~~

自动链接扩展可以把网址直接识别为链接：

~~~markdown
https://example.com
~~~

这些能力并不是所有 Markdown 实现的共同标准。为了保证文章迁移到其他平台后仍然可读，跨平台文档应优先使用最基础、最通用的写法；只有明确知道目标渲染器支持时，再使用脚注、任务列表或数学扩展。

## 十一、Frontmatter 与文章元数据

许多静态博客会在 Markdown 文件开头使用 YAML frontmatter 保存标题、日期、标签和分类：

~~~yaml
---
title: "文章标题"
pubDate: 2026-03-23
description: "文章摘要"
tags: ["Markdown", "写作"]
category: "技术笔记"
draft: false
---
~~~

frontmatter 不属于正文 Markdown，但会参与文章页面标题、归档排序、搜索摘要和分类筛选。日期应使用站点要求的格式；字符串中包含冒号、引号或特殊符号时，要根据 YAML 规则正确加引号。

## 十二、技术博客的写作建议

### 1. 先规划结构，再填充内容

可以先列出文章要解决的问题，再安排“背景—步骤—示例—注意事项—总结”的顺序。标题应准确描述章节内容，避免为了层级而堆叠标题。

### 2. 示例要能独立阅读

命令示例应尽量包含必要的上下文，并说明输入、输出或预期结果。代码块中的路径、变量名和版本号如果只是占位符，最好明确标注，避免读者误以为可以原样执行。

### 3. 统一格式

同一篇文章中应统一使用标题层级、列表符号、代码标记和中英文空格。表格列名要简洁，代码与普通文字之间使用行内代码区分，长文章则通过目录或清晰的二级标题帮助定位。

### 4. 发布前检查

可以按下面的清单进行检查：

- [ ] 标题层级没有跳跃；
- [ ] 链接和图片路径能够访问；
- [ ] 代码块标注了正确的语言；
- [ ] 表格分隔线和列数一致；
- [ ] 需要显示的特殊字符已经转义；
- [ ] 数学公式、HTML 和扩展语法在目标网站中正常渲染；
- [ ] frontmatter 的日期、分类和草稿状态正确；
- [ ] 移动端预览没有严重横向溢出。

## 结语

Markdown 并不是为了替代所有排版工具，而是提供了一种轻量、清晰、可迁移的写作方式。掌握标题、段落、列表、链接、代码和表格等基础语法后，再根据网站能力选择数学公式、任务列表和 HTML 扩展，就足以应对大多数技术博客与项目文档场景。

真正高质量的 Markdown 文章，关键不在于使用了多少语法，而在于结构是否清楚、示例是否准确、内容是否方便读者理解和复用。把语法服务于表达，文章自然会更易读，也更容易长期维护。
