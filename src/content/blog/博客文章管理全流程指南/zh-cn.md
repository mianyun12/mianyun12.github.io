这是“云隐惊雷”博客上线后的第一篇正式文章。建站不易，为了方便后续维护，同时也为了帮助其他使用 Astro 框架搭建博客的同好，特此记录本博客系统的文章更新与清理全流程，并附上部署过程中切实踩过的坑。

## 一、 如何清理自带的演示文章

本博客的所有文章数据均存储在本地仓库的 `src/content/blog/` 目录下。

1. **定位目录**：在代码编辑器左侧的资源管理器中，找到并展开 `src/content/blog/`。
2. **执行删除**：每一个文件夹通常代表一个系列或单篇文章。找到不再需要的演示文章（如 `intro`、`test` 等）所在的文件夹，直接右键删除即可。
3. **优势**：由于采用文件夹分类，删除整个文件夹时会一并清理该文章专属的配图，完全不需要去公共图片库二次排查，非常省心。

## 二、 如何创建并编写新文章

为了保证文章格式规范（如发布时间、标签等元数据正确自动生成），强烈推荐使用项目自带的脚本来生成新文章。

### 1. 运行新建脚本
在代码编辑器终端中，执行以下命令：
```bash
node script/newpost.js "你的新文章标题"
```

> **🚩 避坑指南：执行脚本时的 `MODULE_NOT_FOUND` 报错**
>
> 在运行上述命令时，**一定要确保你的终端路径停留在项目的根目录**！
>
> 如果你顺着资源管理器点进了 `src/content/blog/` 并在该目录下打开终端执行脚本，Node.js 会去当前目录找 `script` 文件夹，从而抛出 `Error: Cannot find module` 报错。
>
> **解决方法**：执行 `cd ../../..` 退回项目根目录，或者在根目录空白处重新打开终端再执行命令。

### 2. 编写正文

脚本执行完毕后，会在 `src/content/blog/` 下生成以你的标题命名的目录及 Markdown 文件。打开该文件，在由 `---` 包裹的头信息（Frontmatter）下方开始撰写正文即可。

## 三、 自动化部署与上线

本地写作和清理完成后，需要将改动推送到 GitHub 仓库触发 GitHub Actions 自动化部署。

在终端（同样需在根目录）依次执行以下 Git 指令：

Bash

```
git add .
git commit -m "docs: 发布全新管理指南并清理演示文章"
git push
```

> **🚩 避坑指南：部署后网页“裸奔”，CSS 排版和图片全部 404 丢失**
>
> 刚部署完第一次访问时，网页可能没有任何样式，全部变成了纯文本。这通常是**静态资源的加载路径（Base URL）错位**导致的。
>
> 在 GitHub Pages 的规则中，只有当仓库名和用户名**完全一致**时（例如用户名是 `1031260154`，仓库名就必须是 `1031260154.github.io`），网站才会部署在根目录 `/` 下。
>
> 如果仓库名取了其他名字（比如 `mianyun.github.io`），网站实际是被放在了子路径里。此时底层的代码依然默认去根目录读取 CSS 和图片，就会全部报错 404。
>
> **解决方法**：
>
> 最干净、最推荐的做法是直接去 GitHub 仓库的 **Settings** 里，将仓库重命名为 `你的用户名.github.io`，并把代码中配置的 `indexPage` 改为对应的根域名。或者修改 `astro.config.mjs` 中的 `base` 字段来适配子路径。

排雷完毕后，只需等待 GitHub Actions 自动构建完成，刷新网址，就能看到排版精美的全新博客了。
