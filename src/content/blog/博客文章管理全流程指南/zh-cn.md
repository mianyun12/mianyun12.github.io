这是搭建专属博客后的第一篇维护指南。为了避免原生 Markdown 语法冲突导致的换行错乱或解析失败，这篇记录去除了大面积的代码包裹，主要以清晰的文本步骤形式留存。

**第一部分：如何清理历史占位文章**

我们的博客源文件全部位于本地的 src/content/blog/ 目录下。

清理操作非常直接：在 VS Code 左侧的资源管理器中，展开该目录，将项目默认自带的 intro、markdown 等演示文件夹直接选中并右键删除即可。以文件夹为单位进行删除的好处是，连同文章绑定的本地测试图片等静态资源也会一并清理，不会给仓库留下冗余素材。

**第二部分：如何生成并编写新文章**

为了确保每篇文章的元数据（如发布时间戳、标签格式等）绝对规范，强烈建议依赖项目自带的脚本，尽量不要手动新建文件。

请在 VS Code 的原生终端面板中，键入并执行以下命令：
python script/newpost.py "你的文章标题"

执行结束后，对应名称的目录和 md 文件就会自动生成。直接点击打开该文件，在头部虚线（Frontmatter）的下方正常录入你的正文即可。

**第三部分：如何同步并触发自动上线**

当文章编写完成，保存文件后，我们就可以通过 Git 工具将改动推送到远端仓库。

请依次在终端输入并回车执行这三条核心指令：

第一条指令：git add . 
（注意最后有一个点，这会将你刚才删除旧文章、新增新文章的所有变动一次性收集到暂存区）

第二条指令：git commit -m "docs: 清理默认文章并发布全新管理指南" 
（为这次更新添加一条清晰的备注信息，方便日后回溯）

第三条指令：git push 
（将上述所有变动正式推送到 GitHub 远端）

随着最后一条指令执行完毕，GitHub Actions 会在云端自动接管编译和打包工作。稍等一两分钟后刷新你的博客网页，干净整洁的新版博客就正式上线了。

```
git add .
git commit -m "1"
git push
```
