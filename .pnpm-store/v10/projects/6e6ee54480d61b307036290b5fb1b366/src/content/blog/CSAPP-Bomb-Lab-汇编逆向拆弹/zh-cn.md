Bomb Lab 不是猜密码，而是把没有源代码的可执行程序当成证据，从比较指令、跳转条件、寄存器变化和内存布局中反推出每一关的约束。每个人下载到的 bomb 都是独立生成的，所以网上的固定答案只能帮助理解格式，不能替代自己的反汇编和调试。

本文保留“观察现象—提出假设—执行验证—发现错误—修正思路—确认答案”的过程。具体地址、密码和输出均是示例，读者必须以自己的 bomb 为准。

## 1. 实验准备：先让输入和工具可靠

### 1.1 获取个人 bomb

在课程远程环境中申请个人 bomb，下载后解压：

~~~shell
tar -xvf bombXXX.tar
cd bombXXX
ls
file bomb
~~~

目录中通常包含 bomb、README 和辅助文件。不要修改服务器生成的压缩包，也不要把他人的 bomb、密码和地址混用。

### 1.2 三个核心工具

~~~shell
gdb ./bomb
objdump -d ./bomb > bomb.s
strings ./bomb
~~~

strings 用于发现明文字符串；objdump -d 用于快速定位函数和跳转；gdb 用于在运行时查看寄存器、栈和内存。

常用指令：

~~~text
break phase_1
run
disassemble phase_1
info registers
x/s 地址
x/16gx rsp
si
ni
continue
~~~

### 1.3 建立答案文件

~~~shell
touch ans.txt
./bomb < ans.txt
~~~

确认一关后再把该行加入答案文件，调试时执行：

~~~text
run < ans.txt
~~~

这样既能保留已经通过的阶段，也能定位是哪一行发生了爆炸。

### 1.4 第一次排错：文本看起来正确但仍然爆炸

在 Windows 编辑器中保存的文件可能使用 CRLF，文件末尾也可能有多余空格或缺少换行。检查真实字节：

~~~shell
cat -A ans.txt
od -An -tx1 -c ans.txt
~~~

如果出现 ^M，需要转换为 LF，或在远程 Linux 中重新创建文件。

> **推理记录**
>
> - 现象：肉眼看到的答案正确，但程序仍然触发爆炸。
> - 判断：程序读取的字节序列和屏幕显示的字符串不一致。
> - 验证：用 cat -A 和十六进制输出查看回车、换行、空格。
> - 修正：移除 CR、尾随空格，保证每行正常结束。
> - 结论：逆向实验要同时检查文本内容和文本编码。

## 2. Phase 1：从字符串比较得到答案

第一关通常把输入和静态字符串比较。先定位函数：

~~~text
break phase_1
run
disassemble phase_1
~~~

重点看：

- 哪条 lea 或 mov 指令加载了字符串地址；
- 用户输入放在第几个参数寄存器；
- 比较函数返回值在哪里；
- 哪个条件跳转会进入爆炸函数。

如果出现类似：

~~~asm
mov imm_0x404158, esi
call strings_not_equal
test eax, eax
jne explode_bomb
~~~

地址不是答案本身，而是答案所在的内存地址：

~~~text
x/s 0x404158
~~~

文档中出现过 “There are rumors on the internets.” 和 “The future will be better tomorrow.” 等示例，但实际字符串取决于个人 bomb。正确答案来自自己的 x/s 输出，并且要保留大小写、空格和句号。

> **推理记录**
>
> - 现象：phase_1 很快跳到爆炸函数。
> - 假设：比较函数返回非零，输入与目标字符串不相等。
> - 验证：读取比较函数参数和静态地址的字符串。
> - 修正：不用猜测，直接复制当前二进制中的字符串。
> - 结论：Phase 1 是静态数据定位题。

## 3. Phase 2：循环、数组和状态转移

第二关通常先用 sscanf 读取六个整数，再循环检查它们之间的关系。先看函数外壳：

~~~text
disassemble phase_2
break phase_2
run
~~~

根据 lea 的目标地址、sscanf 参数和循环中的内存访问，确定六个整数在栈上的位置。文档中出现过典型递推：

~~~text
a[i] = a[i - 1] + i
~~~

这说明第一项可能是自由起点，后续项由循环推导，不一定只有一组合法答案。

看到比例变址寻址时：

~~~asm
mov (rbx,rax,4), eax
~~~

可以翻译为：

~~~c
value = array[index];
~~~

用 GDB 检查数组和循环变量：

~~~text
x/6dw rbx
info registers rax rbx eax edx
display/i pc
si
~~~

### 推理记录：为什么寄存器会不断变化

- 现象：edx 和 eax 的值在每次循环中都不同。
- 假设：一个寄存器保存上一个元素，另一个保存根据下标计算出的期望值。
- 验证：单步执行加法、加载和比较指令，记录每轮状态。
- 修正：把汇编翻译成状态转移表，而不是把每个新数字当成密码。
- 结论：本关本质是数组递推和循环不变量。

## 4. Phase 3：跳转表和条件 flags

### 4.1 先区分 sscanf 返回值和用户输入

函数开头常见：

~~~asm
call __isoc99_sscanf
cmp 1, eax
jle explode_bomb
~~~

eax 此时是成功解析的字段数量，不是第一个用户输入。先确认字段数量检查通过，再分析输入存放的栈地址。

### 4.2 识别跳转表

常见结构如下：

~~~asm
cmp 7, input
ja explode_bomb
mov (table,rax,8), rax
jmp rax
~~~

分析顺序：

1. 找到范围检查，确定第一个输入范围；
2. 找到跳转表基址；
3. 根据输入计算表项；
4. 进入对应 case，记录对结果寄存器的计算；
5. 找到最终和第二个输入比较的位置；
6. 对每个候选 case 推出输入组合。

### 4.3 有符号和无符号跳转

je 根据零标志判断相等；jg 是有符号大于；ja 是无符号高于。不能把所有跳转都翻译成普通的大于。

排查时先写清楚 cmp 实际执行的是谁减谁，再检查 flags：

~~~text
info registers eflags
p/d eax
p/u eax
~~~

> **推理记录**
>
> - 现象：某个 case 产生负数，直觉上认为答案不合法。
> - 假设：这是补码下的正常有符号结果，或当前跳转采用无符号语义。
> - 验证：查看减法方向、flags，并同时按有符号和无符号打印寄存器。
> - 修正：根据跳转指令重新翻译 C 逻辑。
> - 结论：数据解释必须和比较指令的 signed/unsigned 语义一致。

## 5. Phase 4：递归路径和参数配对

先分析 phase_4 外壳，不要直接跳进递归函数：

~~~text
disassemble phase_4
break __isoc99_sscanf
run
info registers rdi rsi rdx rcx
~~~

确认 sscanf 读取了几个字段、哪个字段被限制范围、哪个栈位置被传入 func4。x86-64 调用约定下，参数依次进入 rdi、rsi、rdx、rcx，解析数量在 eax。

一个常见的 func4 是二分递归：

~~~c
int func4(int x, int low, int high) {
    int mid = low + (high - low) / 2;
    if (mid > x)
        return func4(x, low, mid - 1) + ...;
    if (mid < x)
        return func4(x, mid + 1, high) + ...;
    return ...;
}
~~~

逆向只需逐层回答：

1. 中点怎样计算；
2. 小于或大于中点时走哪条分支；
3. 返回时如何乘 2、加 1 或累加路径。

文档中的关键发现是：第一个输入负责选择递归路径，第二个输入是递归返回值的校验结果。它们必须成对推导，不能把不同路径的结果混合。

> **推理记录**
>
> - 现象：第一个数字在范围内，但组合仍然爆炸。
> - 假设：第二个数字不是独立常数，而是路径编码。
> - 验证：在 func4 返回前查看 eax，并对照 phase_4 的最终比较。
> - 修正：先确定路径，再计算路径返回值。
> - 结论：答案是输入、递归路径和返回值的绑定关系。

## 6. Phase 5：低四位和查表映射

常见汇编逻辑：

~~~asm
movzbl (rbx,rax,1), edx
and 0xf, edx
movzbl (table,rdx,1), edx
mov dl, (dest,rax,1)
~~~

对应的推理过程：

1. 取输入第 i 个字符；
2. 保留低四位，索引范围变成 0 到 15；
3. 以低四位为下标查找 16 字符表；
4. 写入目标缓冲区；
5. 比较生成字符串和固定字符串。

在断点处读取密码表和目标字符串：

~~~text
x/s 表地址
x/s 目标地址
~~~

先做目标字符到表下标的反向映射，再找一个低四位相等的 ASCII 字符。文档中出现过 maduiersnfotvbyl 等表内容，但它们只是样例，不适用于所有 bomb。

> **推理记录**
>
> - 现象：随便替换字母不能通过，但多个不同字母似乎可能有效。
> - 判断：程序只使用 ASCII 低四位，高四位被丢弃。
> - 验证：在 and 0xf 前后查看寄存器。
> - 修正：逆向查表关系，而不是直接猜最终字符串。
> - 结论：本关考查位掩码、数组索引和查表逆变换。

## 7. Phase 6：链表、指针和 7-x 映射

### 7.1 识别节点结构

Phase 6 通常读取六个互不相同的整数，将它们转成节点编号，再重排链表。节点常见形式：

~~~c
struct Node {
    int value;
    int id;
    struct Node *next;
};
~~~

汇编中的：

~~~asm
mov 0x8(rax), rax
~~~

通常等价于：

~~~c
node = node->next;
~~~

### 7.2 沿指针找节点，不按地址猜

节点可能分散在内存中，先找到首节点，再查看字段和 next 指针：

~~~text
x/3gx 节点地址
x/6dw 节点地址
x/gx 节点地址+8
~~~

每个节点都记录 value、id 和 next。内存中的干扰数字不能直接当成节点值，必须沿指针逐个确认。

### 7.3 推导 7-x

许多版本先将输入转换为：

~~~text
mapped = 7 - input
~~~

因此要先按节点值推导出逻辑顺序，再反推用户输入。文档中的 3 5 1 6 4 2 只是一次样例，不代表其他 bomb 的答案。

重排后在循环结束处检查 next 指针：

~~~text
x/6gx 节点指针数组地址
x/gx 当前节点地址+8
si
~~~

最后确认程序要求节点值递增还是递减，以及条件跳转使用的是有符号还是无符号比较。

> **推理记录**
>
> - 现象：按内存出现顺序排列节点仍然爆炸。
> - 假设：节点实际顺序由 next 指针决定，输入还经过 7-x 变换。
> - 验证：沿 next 读取所有节点，再逐步执行映射循环。
> - 修正：先按 value 排序，再做编号反变换。
> - 结论：本关同时考查指针追踪、链表重排和输入映射。

## 8. 一条可迁移的逆向证据链

~~~text
输入如何进入寄存器或栈
        ↓
哪条指令决定分支或爆炸
        ↓
分支依赖哪些数据和 flags
        ↓
把局部汇编翻译成 C 逻辑
        ↓
用 GDB 观察中间值
        ↓
推导满足约束的输入
        ↓
写入答案文件并整体验证
~~~

遇到不确定的寄存器，记录指令前后值；遇到不确定的内存，先确认地址来源再用 x/ 查看；遇到不确定的比较，先确认减法方向和 signed/unsigned 语义。

## 9. 最终复盘

Bomb Lab 让我改变了“看到答案字符串就结束”的习惯：

1. 不相信网络上的固定答案，相信当前二进制的证据；
2. 不把寄存器当成抽象变量，而是追踪每条指令前后的变化；
3. 不把爆炸当成终点，而把它当成约束不满足的输出；
4. 不只记录最终密码，还记录从输入到比较指令的转换路径。

即使更换个人 bomb，也能重新通过“定位—翻译—推导—验证”得到答案。
