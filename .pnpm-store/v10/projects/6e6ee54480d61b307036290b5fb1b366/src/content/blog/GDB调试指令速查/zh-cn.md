## 导读

调试器真正发挥作用的前提，是把“程序停在哪里、为什么停下、当前状态是什么”变成可以观察和验证的问题。下面将这份 GDB 指令资料整理为博客文章，保留原有命令示例，方便从源码级调试逐步过渡到寄存器、内存和汇编级分析。

## 启动与基本设置

在开始调试前，请确保在程序编译时增加 `-g` 选项以支持 GDB 调试（例：`gcc -g example.c -o example.x`）。

| **指令 (全拼/简写)**     | **功能描述**                                     | **典型参数与示例**                                           |
| ------------------------ | ------------------------------------------------ | ------------------------------------------------------------ |
| `gdb`                    | 载入可执行程序开始调试                           | **`gdb example.x`**                                          |
| `gdb attach`             | 加载并附加到正在运行的进程进行调试               | **`gdb attach <PID>`**                                       |
| `gdb` + `core`           | 发生段错误时，配合 core dump 文件进行事后调试    | **`gdb example.x core`** (需通过 `ulimit -c unlimited` 开启系统 core dump) |
| `file`                   | 在 GDB 启动后，载入要调试的可执行文件            | **`file ./example.x`**                                       |
| `set args` / `show args` | 设置 / 查看程序运行时的命令行启动参数            | **`set args -p 8080`**                                       |
| `dir`                    | 指定源码搜索目录 (Specifying source directories) | **`dir /path/to/src/`**                                      |
| `kill`                   | 结束当前正在调试的程序进程                       | **`kill`**                                                   |
| `quit` (**`q`**)         | 退出 GDB 调试环境                                | **`q`**                                                      |

## 程序运行控制

| **指令 (全拼/简写)**              | **功能描述**                                                 | **典型参数与示例**                                      |
| --------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------- |
| `start`                           | 开始执行程序，停在 `main` 函数第一行语句前等待命令           | **`start`**                                             |
| `run` (**`r`**)                   | 从头开始连续运行程序，直到遇到断点或程序结束                 | **`r`** (可在后面直接加参数，如 **`r -c config.json`**) |
| `run <` / `>`                     | 使用重定向符号 `<` 和 `>` 将程序的标准输入/输出重定向到文件  | **`r < in.txt > out.txt`**                              |
| `continue` (**`c`** / **`cont`**) | 从当前位置继续连续运行程序，跳过当前断点                     | **`c`** / **`c 5`** (跳过 5 次断点后继续运行)           |
| `step` (**`s`**)                  | 单步执行源代码。遇到函数调用时，**会进入**函数内部           | **`s`** / **`s 3`** (连续执行 3 条语句)                 |
| `next` (**`n`**)                  | 单步执行源代码。遇到函数调用时，**跳过**子程序，不进入内部   | **`n`** / **`n 5`** (连续执行 5 条语句)                 |
| `stepi` (**`si`**)                | **[底层扩充]** 汇编级单步执行。遇到 call 指令**会进入**子函数 | **`si`** (常配合 `display/i $pc` 使用)                  |
| `nexti` (**`ni`**)                | **[底层扩充]** 汇编级单步执行。遇到 call 指令**不会进入**子函数 | **`ni`**                                                |
| `until` (**`u`**)                 | **[底层扩充]** 执行程序直到跳出当前循环体，常用于快速脱离长循环 | **`u`** / **`u 行号`** (执行直到达到指定行)             |
| `finish`                          | 继续执行直到当前函数返回，打印返回值后暂停                   | **`finish`**                                            |
| `jump`                            | 强制程序跳转到指定行开始执行（注意：可能破坏上下文）         | **`jump 125`**                                          |

## 断点与观察点

| **指令 (全拼/简写)**           | **功能描述**                                                | **典型参数与示例**                                 |
| ------------------------------ | ----------------------------------------------------------- | -------------------------------------------------- |
| `break` (**`b`**)              | 在特定位置设置断点                                          | **`b 25`** (行号) / **`b func_name`** (函数开头)   |
| `tbreak`                       | 设置临时断点，命中一次后自动删除                            | **`tbreak 30`**                                    |
| `break ... if ...`             | 设置条件断点，当条件表达式为真时才暂停                      | **`b 50 if i == 10`**                              |
| `info breakpoints` (**`i b`**) | 查看当前设置了哪些断点及详细信息（命中次数、启用状态等）    | **`i b`**                                          |
| `watch`                        | 设置写观察点：当变量或表达式的值**发生改变**时暂停程序      | **`watch var_name`** (必须在 `run` 之后设置)       |
| `awatch`                       | 设置读写观察点：当变量的值被**改变或读取**时暂停程序        | **`awatch var_name`**                              |
| `rwatch`                       | **[底层扩充]** 设置读观察点：当变量的值被**读取**时触发暂停 | **`rwatch ptr`**                                   |
| `info watchpoints`             | 查看当前设置了哪些观察点                                    | **`info watchpoints`**                             |
| `delete` (**`d`**)             | 删除指定断点或自动显示的表达式。无参数时默认删除所有断点    | **`delete 1`** (删除1号断点) / **`d breakpoints`** |
| `clear`                        | 清除指定行号或函数上的断点                                  | **`clear 25`** / **`clear func_name`**             |
| `disable` / `enable`           | 禁用 / 恢复启用指定编号的断点                               | **`disable 1 2`** / **`enable breakpoints 1`**     |
| `ignore`                       | 忽略某断点指定的次数                                        | **`ignore 1 5`** (忽略 1 号断点接下来的 5 次触发)  |
| `condition`                    | 修改现有断点的触发条件                                      | **`condition 1 num > 100`** (为 1 号断点附加条件)  |
| `commands`                     | 设置遇到指定断点后自动执行的脚本指令                        | **`commands 1`** `> print x` `> continue` `> end`  |

## 内存与寄存器探查

| **指令 (全拼/简写)**           | **功能描述**                                               | **典型参数与示例**                                           |
| ------------------------------ | ---------------------------------------------------------- | ------------------------------------------------------------ |
| `print` (**`p`**)              | 打印变量或表达式的值，也可以通过表达式修改变量或调用函数   | **`p var`** / **`p func()`** / **`p $_`** (查看 search 命令保存的行号)。支持魔法变量 **`$`** (前一个序号) 和 **`$$`** (前两个序号) |
| `x`                            | 从特定内存地址开始，格式化打印一段内存内容。格式为 `x/NxF` | **`x/28hx 0x123456`** (打印28个半字，十六进制显示) **`x/10xw $pc`** (打印接下来的10个字指令) |
| `info registers` (**`i r`**)   | **[底层扩充]** 查看当前 CPU 通用寄存器的值                 | **`i r`** (查看所有通用寄存器) / **`i r eax`** (查看特定寄存器) |
| `display`                      | 跟踪查看一个变量，每次程序暂停时都会自动打印它的值         | **`display var_name`**                                       |
| `info display`                 | 查看当前所有的自动显示项（包含表达式编号）                 | **`info display`**                                           |
| `undisplay` / `delete display` | 取消对特定编号变量的自动跟踪显示                           | **`undisplay 1`**                                            |
| `disable / enable display`     | 暂时禁用 / 恢复特定的自动显示项                            | **`disable display 1`**                                      |
| `whatis`                       | 显示某个变量或表达式的基础数据类型                         | **`whatis ptr`**                                             |
| `ptype`                        | 显示数据类型的详细结构（包含 struct/class/typedef 展开）   | **`ptype var_name`**                                         |
| `set var` / `set`              | 在调试过程中动态修改变量的值                               | **`set var = 10`** / **`set var:=10`**                       |

## 调用栈与上下文

| **指令 (全拼/简写)**           | **功能描述**                                                 | **典型参数与示例**                                 |
| ------------------------------ | ------------------------------------------------------------ | -------------------------------------------------- |
| `backtrace` (**`bt`**)         | 打印当前的函数调用栈帧 (Stack Frame) 信息                    | **`bt`** (打印全部) / **`bt 5`** (打印顶层5个栈帧) |
| `frame` (**`f`**)              | 选择并切换到指定的栈帧进行查看                               | **`f 2`** (切换到2号栈帧)                          |
| `info frame`                   | 显示当前被选中栈帧的详细底层信息（如返回地址、保存的寄存器等） | **`info frame`**                                   |
| `select-frame`                 | 仅选择栈帧，不打印信息（常用在脚本中静默切换）               | **`select-frame 2`**                               |
| `info locals` (**`i locals`**) | 查看当前所在栈帧的所有**局部变量**的值                       | **`i locals`**                                     |
| `info args`                    | **[底层扩充]** 查看当前所在栈帧的**函数传入参数**的值        | **`info args`**                                    |

## 汇编与代码映射

| **指令 (全拼/简写)**        | **功能描述**                                                 | **典型参数与示例**                                           |
| --------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `list` (**`l`**)            | 列出源码。默认接着上次位置继续往下列 10 行                   | **`l`** (按回车可重复)                                       |
| `list` 扩展参数             | 按行号、函数名或相对位置列出源码                             | **`l 20`** (20行附近) / **`l func`** / **`l -`** (往回列10行) |
| `search` / `forward`        | 从当前行向后搜索匹配特定字符串的源码行                       | **`search "error"`** (结果保存在 `$_` 中)                    |
| `reverse-search`            | 从当前行向前搜索匹配特定字符串的源码行                       | **`reverse-search "init"`**                                  |
| `disassemble` (**`disas`**) | **[底层扩充]** 反汇编当前函数或指定地址范围的代码            | **`disas`** / **`disas main`** / **`disas 0x400500, 0x400520`** |
| `layout`                    | **[底层扩充]** 开启 TUI 图形化代码/汇编分屏模式，底层调试神器 | **`layout src`** (看源码) / **`layout asm`** (看汇编) / **`layout regs`** (看寄存器与汇编切分) |

**💡 工程师小贴士：** 在 GDB 中如果不记得具体指令，可以随时键入 **两次 Tab 键** 进行自动补全；或者使用 **`help <command>`** 查看任何指令的详细文档（例如 `help x` 可以看到所有内存格式化排版的后缀说明）。对于 Python 脚本，在 Linux 下则可以切换使用 `pdb` 工具进行类似逻辑的调试。

## 小结

使用 GDB 时不必一次记住所有命令。可以先用 `start`、`break`、`next` 和 `print` 建立基本调试流程，再根据问题需要扩展到观察点、调用栈、内存查看和 TUI 汇编界面。
