Data Lab 表面上是“把几个函数补出来”，真正训练的却是另一种能力：当高级语言的常规工具被限制后，能不能从位级表示重新建立问题模型，再用实验工具验证自己的推理。

这篇文章保留我在实验中反复经历的路径：先读约束，接着观察输入和输出，再提出位级假设，最后用 `dlc`、`btest` 或边界样例确认。文中出现的命令以课程远程 Linux 环境为准；课程平台地址属于校内环境，公开阅读时不需要访问这些地址。

## 1. 先理解实验到底限制了什么

### 1.1 我最初的理解：只是实现 20 个函数

实验说明要求在 `bits.c` 中完成一组整数和浮点数函数。每个函数有功能描述、允许的运算符、最大运算符数量和难度等级。最容易犯的错误是只关注“算出正确结果”，忽略了实现本身也会被检查。

因此每一道题实际上有两个目标：

1. 数学结果正确；
2. 代码符合题目规定的表达式形式。

整数题的基本规则包括：只能使用题目允许的常量、参数、局部变量和位运算；不能使用 `if`、循环、宏、函数调用、类型转换、数组、结构体或其他数据类型。浮点题放宽了控制流和 `unsigned` 的使用，但仍然不能直接使用浮点运算。

### 1.2 推理记录：为什么要先读 `bits.c`

> **推理记录**
>
> - 现象：实验说明和 `bits.c` 头部注释中的最大操作数有时并不完全一致。
> - 判断：评分器真正检查的是当前 handout 中的源文件规则。
> - 验证：以 `bits.c` 函数注释、`dlc` 输出和 `btest` 输出交叉确认。
> - 结论：写题前先读函数注释；说明文档只提供背景，源码中的规则优先级更高。

### 1.3 三类题型

| 类型 | 识别特征 | 常用方法 |
| --- | --- | --- |
| 位运算 | 只允许 `~ & ^ | + << >>` 等操作 | 恒等式、掩码、移位和符号扩展 |
| 补码运算 | 判断正负、溢出、大小关系或取整 | 符号位、异或、算术右移、偏置 |
| 浮点位级运算 | 参数是 `unsigned`，但代表 IEEE 754 位模式 | 拆分符号位、阶码、尾数后分类处理 |

这个分类帮助我在看到题目时先判断“应该使用哪种套路”，而不是一上来尝试写 C 语言条件分支。

## 2. 环境准备：先让实验工具能运行

### 2.1 获取并解压 handout

课程平台提供 `datalab-handout.tar`。在课程远程桌面中下载后，打开终端，将文件复制到当前目录并解压：

```shell
cp /mnt/cgshare/datalab-handout.tar ./
tar xvf datalab-handout.tar
cd datalab-handout
```

这里的 `/mnt/cgshare` 是课程远程桌面与上传区域之间的共享目录。解压后应看到 `bits.c`、`dlc`、`btest` 相关源文件、`driver.pl` 和 Makefile 等内容。

### 2.2 配置个人标识文件

课程服务器会为每个学号生成一次绑定的哈希值。拿到值后，需要在实验目录中创建 `stuID` 文件：

```shell
vi stuID
```

在 vi 中按 `i` 进入插入模式，将哈希值粘贴进去；按 `Esc`，输入 `:wq`，再按回车保存退出。检查文件是否存在：

```shell
ls
```

这里有一个容易被忽略的细节：`:wq` 中的冒号、`w`、`q` 都要输入，不能把它当成普通文本写进文件。没有 `stuID`，后续在线提交可能不会被服务器接收。

### 2.3 第一次遇到 `Permission denied`

执行检查器时可能看到：

```text
bash: ./dlc: Permission denied
```

这不是代码错误，而是文件没有执行权限。修复后重新运行：

```shell
chmod +x dlc
./dlc bits.c
```

如果没有任何输出，通常表示编码规则检查通过。实验过程中只要修改了 `bits.c`，都应该重新运行 `dlc`。

### 2.4 功能测试和增量编译陷阱

第一次可以这样编译并运行：

```shell
make btest
./btest
```

如果修改了 `bits.c`，不能只凭感觉再次运行旧的 `btest`。为了避免测试程序仍然使用旧的目标文件，先清理再重新编译：

```shell
make clean
make btest
./btest
```

定位单道题时，可以使用：

```shell
./btest -h
./btest -f foo
./btest -f foo -1 27 -2 0xf
```

### 2.5 推理记录：看到 warning 要不要停

> **推理记录**
>
> - 现象：运行 `dlc` 时出现 `Non-includable file <command-line> included ...` warning。
> - 判断：这是编译环境的提示，不一定与待实现函数的逻辑有关。
> - 验证：确认 `dlc` 没有报告非法操作符，随后用 `btest` 检查实际结果。
> - 结论：不能把所有 warning 都当成失败；要区分编码规则错误、功能测试失败和环境提示。

## 3. 整数位运算：从限制反推出解法

### 3.1 `bitXor`：只用 `~` 和 `&` 构造异或

题目要求用 `~` 和 `&` 实现 `x ^ y`。观察真值表后发现，异或是“至少一个为 1，但不能同时为 1”：

```text
x ^ y = (x & ~y) | (~x & y)
```

但题目不允许 `|`，因此继续使用德摩根律：

```text
a | b = ~(~a & ~b)
```

代入得到：

```c
int bitXor(int x, int y) {
    return ~(~(x & ~y) & ~(~x & y));
}
```

推理过程的关键不是背表达式，而是先拆成两个互斥情况，再用德摩根律把禁止的 `|` 消掉。最后用 `bitXor(4, 5)` 等样例和 `dlc` 验证操作数数量。

### 3.2 `bang`：不用 `!` 判断零

题目要求 `bang(0)=1`，非零返回 0，且不能使用 `!`。我先观察一个事实：非零整数 `x` 和 `-x` 中至少有一个最高位为 1；只有 `x=0` 时，二者的最高位都为 0。

补码中 `-x` 可以写成 `~x + 1`。因此把 `x` 与 `-x` 合并后右移 31 位：

```c
int bang(int x) {
    return ((x | (~x + 1)) >> 31) + 1;
}
```

验证两个边界：

- `x=0`：`x | -x` 仍为 0，算术右移得到 0，再加 1 得 1；
- `x=3` 或任意非零值：最高位变成 1，右移得到 `-1`，再加 1 得 0。

### 3.3 `copyLSB`：从一个位扩展成全字

`copyLSB(5)` 应为 `0xffffffff`，`copyLSB(6)` 应为 `0x00000000`。先取最低位，再利用符号扩展：

```c
int copyLSB(int x) {
    return ((x & 1) << 31) >> 31;
}
```

当最低位为 1 时，左移到符号位，再算术右移会把 1 扩展到所有位；最低位为 0 时结果保持全 0。

### 3.4 `oddBits`：从一个字节模式扩展到 32 位

奇数编号位为 1 的低 8 位模式是 `0xaa`。由于整数题的常量不能直接写很大的数，先构造低 16 位，再复制到高 16 位：

```c
int oddBits(void) {
    int mask = 0xAA | (0xAA << 8);
    return mask | (mask << 16);
}
```

这里体现了一个通用方法：常量受限时，先用允许的 8 位常量构造局部模式，再用移位和按位或复制。

### 3.5 `isAsciiDigit`：把区间判断改写成符号位判断

目标是判断 `0x30 <= x <= 0x39`。不能直接写比较时，可以分别判断 `x-0x30` 和 `0x39-x` 是否为非负数。

```c
int isAsciiDigit(int x) {
    int lower = x + ~0x30 + 1;
    int upper = 0x39 + ~x + 1;
    return !(lower >> 31) & !(upper >> 31);
}
```

推理过程中最容易犯的错是只判断上界，导致 `0x05` 这样的数被误判为合法；也可能只判断低位而忽略高位溢出。区间题要拆成“下界成立”和“上界成立”两个条件。

## 4. 补码运算：为什么负数需要单独思考

### 4.1 负数右移并不等于向零取整

在 CSAPP 的假设中，有符号整数右移是算术右移。对正数而言，右移 3 位通常等价于除以 8；但对负数，算术右移趋向负无穷，而 C 语言整数除法要求结果向零截断。

例如某个负数除以 8 的真实结果是 `-1.5`：

- 算术右移得到 `-2`；
- C 语言整数除法应得到 `-1`。

因此在右移前需要给负数加上 `2^k-1` 的偏置。除以 8 时偏置为 7：

```c
int sign = x >> 31;
int bias = sign & 7;
return (x + bias) >> 3;
```

### 4.2 `multFiveEighths`：先避免乘法溢出，再修正取整

直接写 `x * 5 >> 3` 有两个问题：乘 5 可能先溢出，负数右移又可能产生向下取整。更稳妥的思路是把 `x` 拆为高位商和低位余数：

```text
x = (x >> 3) * 8 + (x & 7)
x * 5 / 8 = (x >> 3) * 5 + ((x & 7) * 5) / 8
```

实现时只对负数余数部分加偏置：

```c
int multFiveEighths(int x) {
    int q = x >> 3;
    int r = x & 7;
    int sign = x >> 31;
    int main = q + (q << 2);
    int rest = ((r + (r << 2)) + (sign & 7)) >> 3;
    return main + rest;
}
```

排查过程的核心是用正数、负数、0、接近 `INT_MAX` 和接近 `INT_MIN` 的值分别测试，而不是只用题目给的普通样例。

### 4.3 `trueFiveEighths`：为什么还要拆高低位

当题目明确要求避免中间溢出时，`x*5` 不能直接计算。拆分后，`q=x>>3` 的量级已经缩小，`q*5` 更安全；余数只有 3 位，`r*5` 不会溢出。这个“先拆除数部分和余数部分，再分别计算”的方法可以迁移到很多需要在有限位宽内实现有理数运算的题目。

## 5. IEEE 754：从“直接改指数”到完整边界处理

### 5.1 先拆位域，而不是把 `unsigned` 当普通整数

单精度浮点数的 32 位布局是：

```text
31             23              0
+---------------+---------------+
| sign 1 bit    | exp 8 bits    | frac 23 bits |
+---------------+---------------+
```

常用提取代码：

```c
unsigned sign = uf & 0x80000000;
unsigned exp  = uf & 0x7f800000;
unsigned frac = uf & 0x007fffff;
```

分类规则：

- `exp == 0x7f800000`：阶码全 1，是无穷大或 NaN；
- `exp == 0`：非规格化数或 0；
- 其他：规格化数。

### 5.2 `float_twice`：先判断特殊值，再处理指数和尾数

最初的直觉是所有数都把阶码加 1，但非规格化数没有隐含的最高位，不能这么处理。正确推理顺序是：

1. 阶码全 1，直接返回原位模式；
2. 阶码为 0，尾数左移一位，可能从非规格化数进入规格化数；
3. 规格化数把阶码增加一个 `1 << 23`；
4. 如果阶码变成全 1，尾数必须清零，表示无穷大。

```c
unsigned float_twice(unsigned uf) {
    unsigned sign = uf & 0x80000000;
    unsigned exp = uf & 0x7f800000;
    unsigned frac = uf & 0x007fffff;

    if (exp == 0x7f800000)
        return uf;
    if (exp == 0) {
        frac <<= 1;
    } else {
        exp += 0x00800000;
        if (exp == 0x7f800000)
            frac = 0;
    }
    return sign | exp | frac;
}
```

### 5.3 `float_half`：第一次写法为什么还不够

对普通规格化数，除以 2 可以把阶码减 1；对特殊值，直接返回；但当阶码为 1 时，减 1 会进入非规格化数，必须把隐含的最高位加入尾数后右移。非规格化数同样要右移尾数。

只写 `frac >>= 1` 会漏掉两个细节：

- 规格化数跨入非规格化数时，隐含位 `0x800000` 必须并入尾数；
- 右移时需要按照 IEEE 754 的偶数舍入规则处理被移出的位。

因此完整的 `k=1` 思路是：

```c
unsigned float_half(unsigned uf) {
    unsigned sign = uf & 0x80000000;
    unsigned exp = uf & 0x7f800000;
    unsigned frac = uf & 0x007fffff;

    if (exp == 0x7f800000)
        return uf;

    if (exp == 0 || exp == 0x00800000) {
        unsigned combined = frac | exp;
        unsigned round = (combined & 3) == 3;
        return sign | ((combined >> 1) + round);
    }

    return uf - 0x00800000;
}
```

这里的 `round` 来自“右移一位时，被丢弃部分大于半数，或恰好为半数且保留结果为奇数”的判断。实验中如果普通样例都通过、边界测试失败，应该优先检查这里，而不是怀疑位域掩码。

### 5.4 浮点题的通用排查表

| 观察到的失败 | 优先检查的假设 |
| --- | --- |
| NaN 被改写 | 是否在阶码全 1 时直接返回 |
| 最小规格化数结果错误 | 是否把隐含位并入尾数 |
| 非规格化数乘 2 错误 | 左移后是否发生进位并升级阶码 |
| 除 2 的边界值相差 1 | 是否做了偶数舍入 |
| 无穷大变成普通数 | 阶码溢出后是否清零尾数 |

## 6. `byteSwap`：先置零，再用 `|` 替换

### 6.1 观察题目示例确定字节编号

题目示例：

```text
byteSwap(0x12345678, 1, 3) = 0x56341278
```

从结果反推，第 1 个字节是 `0x56`，第 3 个字节是 `0x12`。因此本题按最低有效字节开始编号：第 0 字节位于 bit7~bit0。

这个判断很重要，因为“字节编号”和“内存小端序”容易被混为一谈。C 语言的移位操作针对整数数值，不是直接遍历内存字节。

### 6.2 推导固定套路

1. 字节编号转位偏移：`n_shift = n << 3`，`m_shift = m << 3`；
2. 提取目标字节：`(x >> shift) & 0xff`；
3. 合并目标位置的全 1 掩码，再整体取反，把两个位置清零；
4. 将两个提取结果交换位置，用 `|` 合并。

```c
int byteSwap(int x, int n, int m) {
    int n_shift = n << 3;
    int m_shift = m << 3;
    int n_byte = (x >> n_shift) & 0xff;
    int m_byte = (x >> m_shift) & 0xff;
    int mask = ~((0xff << n_shift) | (0xff << m_shift));

    return (x & mask) | (n_byte << m_shift) | (m_byte << n_shift);
}
```

### 6.3 手算验证和错误排查

对于 `0x12345678, 1, 3`：

```text
n_shift = 8,  m_shift = 24
n_byte  = 0x56, m_byte = 0x12
mask    = ~(0x0000ff00 | 0xff000000)
        = 0x00ff00ff
```

清零后保留 `0x00340078`，再放入 `0x56` 和 `0x12`，得到 `0x56341278`。

最初容易出现的错误有三个：把第 0 字节理解成最高位、提取后忘记 `& 0xff`、用 `+` 而不是 `|` 合并。逐步写出中间值后，这些错误会立即暴露。

## 8. 方法总结

Data Lab 的核心不是背某个函数的最终代码，而是建立三条稳定的推理链：

1. **位模式链**：先确定每一位表示什么，再决定移位、掩码和合并方式；
2. **补码链**：先判断符号、溢出和取整方向，再决定是否需要符号掩码或偏置；
3. **验证链**：普通样例通过不等于边界正确，必须用 `dlc` 检查形式、用 `btest` 检查功能，再用极值和特殊值检查推理漏洞。

当一个答案失败时，最有效的问题不是“哪一行写错了”，而是：我当前假设的是位级事实、补码事实，还是 IEEE 754 分类事实？先定位假设，再修改表达式，排错速度会快很多。
