## 导读

覆盖率工具的价值，不只是给出一个百分比，更重要的是帮助我们确认测试用例真正走过了哪些代码路径。本文将原有的 gcov 指令整理为一篇可直接查阅的实践手册，适合在 C/C++ 项目测试、实验报告和工程排障时快速定位命令。

### 图内指令与参数解析

根据终端运行记录，完整的执行流包含了从编译插桩、程序运行到覆盖率分析的三个阶段：

```bash
# 1. 编译并注入覆盖率测试桩代码
gcc -fprofile-arcs -ftest-coverage calc.c -o calc

# 2. 运行目标程序，生成执行路径数据
./calc

# 3. 解析数据并生成覆盖率报告
gcov calc.c

```

**相关选项与参数汇总表：**

| 参数/选项         | 作用阶段      | 功能详细说明                                                 | 专家备注                                                     |
| ----------------- | ------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `-fprofile-arcs`  | `gcc` 编译期  | 在编译时插入控制流弧的统计代码。程序运行结束后，会在同目录下生成记录运行数据的 `.gcda` 文件。 | 系统级开发中，常结合 Makefile 统一定义在 `CFLAGS` 中。       |
| `-ftest-coverage` | `gcc` 编译期  | 配合生成代码覆盖率所需的附加信息，编译时会生成包含程序基本块和行号映射关系的 `.gcno` 文件。 | 必须与 `-fprofile-arcs` 联合使用。                           |
| `-h`              | `gcov` 运行期 | 显示 `gcov` 命令的帮助信息并退出。                           | -                                                            |
| `-v`              | `gcov` 运行期 | 显示 `gcov` 的版本信息并退出。                               | -                                                            |
| `-a`              | `gcov` 运行期 | （`--all-blocks`）输出所有基本块（Basic Block）的执行计数。如果一行包含多个基本块，它将输出每个块的具体执行次数。 | 对于包含复杂单行宏定义或内联函数的 C 代码非常有用。          |
| `-n`              | `gcov` 运行期 | （`--no-output`）仅在终端输出统计汇总信息，**不创建** `.gcov` 源码标注文件。 | *注：截图中描述“并创建输出文件”疑似文档笔误，标准 gcov 行为是禁止生成输出文件。* |

### 标准工作流总结

根据终端（图 2）演示的实机操作记录，使用 `gcov` 分析 C 语言程序的标准规范流程可概括为以下三步：

1. **编译构建 (Compile & Instrument)**
使用带有 `-fprofile-arcs -ftest-coverage` 标志的 `gcc` 命令编译源文件（如 `calc.c`）。
* **行为特征**：生成可执行文件 `calc`，并同时生成 `.gcno`（gcov notes）文件，该文件记录了程序的控制流图信息。


2. **执行测试 (Execute & Profile)**
在受控环境下直接运行编译出的可执行程序（如 `./calc`）。
* **行为特征**：程序按设计逻辑执行（图中演示了触发正常的加法逻辑 `3 + 4 = 7` 和异常捕捉逻辑 `Division by zero caught`）。程序正常退出时，会在当前目录生成 `.gcda`（gcov data）文件，记录每条边的实际执行次数。


3. **分析报告 (Analyze & Report)**
执行 `gcov [源文件名]`（如 `gcov calc.c`）命令。
* **行为特征**：`gcov` 会读取 `.gcno` 和 `.gcda` 文件，在终端打印出代码的总行数覆盖率（如 `70.59%`），并在当前目录生成以 `.c.gcov` 为后缀的文本文件。打开该文件即可查看具体到每一行的执行次数。

### 高频进阶参数补充

在实际的 C/C++ 项目工程（如操作底层的系统仿真、调度器或协议栈）中，仅看“行覆盖率”往往不足以保证系统的健壮性，以下是极为常用且图中未提及的进阶参数：

| 高频参数 | 全称                     | 功能解析                                                     | 适用工程场景                                                 |
| -------- | ------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **`-b`** | `--branch-probabilities` | **输出分支覆盖率。** 不仅告诉你某行代码是否执行，还会告诉你该行的所有条件分支（如 `if` 的 true/false，`switch` 的各个 `case`）是否都被触发过。 | 编写高可靠性底层逻辑时必备。必须确保边界条件和异常错误分支都被测试用例覆盖。 |
| **`-f`** | `--function-summaries`   | **输出函数级别的覆盖率摘要。** 在终端打印出每个独立函数的覆盖率百分比。 | 当一个 `.c` 文件包含数十个工具函数时，可快速定位哪个模块缺乏测试。 |
| **`-c`** | `--branch-counts`        | **显示具体的分支执行次数。** （需结合 `-b` 使用）将默认的分支概率百分比替换为具体的命中次数。 | 分析特定死锁或热点循环时，查看条件判断的绝对通过次数。       |
| **`-p`** | `--preserve-paths`       | **保留完整路径。** 生成的 `.gcov` 文件名将包含完整的绝对目录路径信息（把 `/` 替换为 `#`）。 | 大型项目中多个目录存在同名源文件（如 `utils.c`）时，防止生成的覆盖率文件互相覆盖。 |

**高频工程使用示例：**

```bash
# 生成包含分支覆盖率和函数级摘要的报告
gcov -b -f calc.c

# 预期终端输出示例：
# Function 'main'
# Lines executed:85.00% of 20
# Function 'divide'
# Lines executed:100.00% of 5
# File 'calc.c'
# Lines executed:88.00% of 25
# Branches executed:80.00% of 10
# Taken at least once:70.00% of 10
# Creating 'calc.c.gcov'

```

## 小结

这份手册可以作为 gcov 的日常入口：先完成插桩和运行，再读取报告，最后根据分支与函数摘要补齐测试盲区。实际使用时，请结合项目的编译参数、测试数据和生成文件位置进行验证。
